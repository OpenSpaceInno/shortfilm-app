## 1. Unified Response Envelope

Every API response emitted by the NestJS application adheres to a uniform structure, enforced via a global NestJS `ResponseInterceptor`.

### 1.1 Success Response Schema
```json
{
  "success": true,
  "data": {
    "id": "01HTXYZ123456789ABCDEFGHJK",
    "title": "The Missing Phone",
    "slug": "the-missing-phone",
    "isInteractive": true
  },
  "meta": {
    "timestamp": "2026-09-29T08:30:00.000Z",
    "correlationId": "req-9a8b7c6d-5e4f-3a2b"
  }
}
```

### 1.2 Paginated Response Schema
```json
{
  "success": true,
  "data": [
    { "id": "...", "title": "The Missing Phone" },
    { "id": "...", "title": "Rooftop Monsoon" }
  ],
  "meta": {
    "pagination": {
      "page": 1,
      "limit": 20,
      "totalRecords": 84,
      "totalPages": 5,
      "hasNextPage": true,
      "hasPrevPage": false
    },
    "correlationId": "req-9a8b7c6d-5e4f-3a2b"
  }
}
```

## 2. Standardized Error Envelope

Errors are intercepted globally via an `AllExceptionsFilter` which translates domain exceptions, HTTP errors, and validation errors into a stable, machine-readable format. **Stack traces are never exposed in production responses.**

### 2.1 Error Response Schema
```json
{
  "success": false,
  "error": {
    "code": "STORY_VERSION_NOT_PUBLISHED",
    "message": "The requested story version is not available for streaming.",
    "details": [
      {
        "field": "versionId",
        "issue": "Version status is DRAFT and requires approval."
      }
    ],
    "correlationId": "req-9a8b7c6d-5e4f-3a2b"
  }
}
```

### 2.2 Standard Error Codes Registry

| HTTP Status | Error Code | Common Trigger Scenario |
| :--- | :--- | :--- |
| `400 Bad Request` | `VALIDATION_ERROR` | Request payload failed class-validator rules |
| `401 Unauthorized` | `AUTHENTICATION_REQUIRED` | Missing, expired, or invalid JWT token |
| `401 Unauthorized` | `TOKEN_EXPIRED` | Access token expired; trigger `/api/v1/auth/refresh` |
| `403 Forbidden` | `VIP_ENTITLEMENT_REQUIRED` | Premium episode requested without active VIP subscription |
| `403 Forbidden` | `INSUFFICIENT_PERMISSIONS` | Role lacks authority to execute administrative action |
| `404 Not Found` | `RESOURCE_NOT_FOUND` | Story, episode, or node does not exist |
| `409 Conflict` | `DUPLICATE_CHOICE_SUBMISSION`| User has already committed a choice for this node |
| `409 Conflict` | `STORY_VERSION_LOCKED` | Attempted mutation of an immutable `PUBLISHED` version |
| `422 Unprocessable`| `INVALID_STORY_BRANCH` | Choice references non-existent destination node |
| `429 Too Many Req.`| `RATE_LIMIT_EXCEEDED` | Client exceeded IP or user quota thresholds |
| `500 Server Error` | `INTERNAL_SERVER_ERROR` | Unhandled runtime exception (logged with correlation ID) |

## 3. Query Parameter Standards

### 3.1 Pagination
- **Offset Pagination (Admin & Tables):**
  - `?page=1&limit=25` (Maximum limit: 100)
- **Cursor Pagination (Consumer Infinite Scroll Feeds):**
  - `?cursor=01HTXYZ123456789ABCDEFGHJK&limit=20`

### 3.2 Filtering
- Filter criteria use bracket notation:
  - `?filter[genre]=Thriller`
  - `?filter[status]=PUBLISHED`
  - `?filter[isInteractive]=true`

### 3.3 Sorting
- Multi-column sort uses comma-separated field names. Prepend `-` for descending:
  - `?sort=-created_at,title` (Sort by newest first, then alphabetical)

## 4. Idempotency & Concurrency Headers

For state-mutating requests (payments, creator submissions, story publishing):
- **`Idempotency-Key: <UUIDv4>`**: The API checks Redis for this key. If an identical key was processed within 24 hours, the cached response is returned immediately without re-executing business logic.
- **`X-Correlation-ID: <UUIDv4>`**: Attached to all incoming requests by Cloudflare / API Gateway, or auto-generated by NestJS middleware. Echoed in all response headers and embedded in all structured logs.
